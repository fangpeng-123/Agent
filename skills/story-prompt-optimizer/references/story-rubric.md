# Story Prompt Rubric

Use this rubric when `result_judge` reviews output generated by `prompt_tester`.

The reviewer is Codex in the first version. The rules below are the source of judgment; do not invent unrelated criteria.

## Pass Rule

The result passes only when:

- The output satisfies the user's stated task.
- The score is at least the configured `loop.pass_score`.
- No hard-fail item appears.

## Scoring

Start from 100 and subtract points for failures.

- Hard failure: subtract 25 to 40 points.
- Important missing requirement: subtract 10 to 25 points.
- Style or quality weakness: subtract 5 to 15 points.
- Minor wording issue: subtract 1 to 5 points.

## Required Checks

### Requirement Fit

- The output follows the user's requested task.
- The output does not add unrelated scope.
- The output can be used for the intended prompt task without extra explanation.

### Prompt Structure

- Role, task, rules, context, and output format are clear.
- Stable role settings are separated from runtime context.
- The prompt makes clear which inputs are supplied at runtime.
- The prompt has enough constraints to produce consistent output.

### Children's SEL Story Quality

Apply this section when the task involves children's SEL stories.

- The content is suitable for 3-6 year old children.
- SEL goals are embedded in story behavior instead of direct preaching.
- Character traits, growth direction, and conflict sources are clear.
- The story or prompt keeps role cards stable and avoids hardcoding runtime context.
- Interaction points are clear when interaction is required.
- The prompt supports user changes during story progression when required.

### Forbidden Output

Hard-fail the result if it includes:

- Emoji when the prompt forbids emoji.
- Bracketed action or emotion notes in character dialogue when forbidden.
- Adult-style psychological analysis in children's story output.
- Abstract moralizing such as "we should learn to...".
- Extra characters when the prompt restricts the cast.
- Tables, images, or non-text output when plain text is required.
- Runtime context written into role cards as fixed identity.

### Format Stability

- Required sections appear in the requested order.
- JSON output is valid JSON when JSON is requested.
- Markdown output uses the requested heading and list structure.
- Dialogue format follows the requested speaker format.

## Judgment Output

Return a structured judgment in this shape:

```json
{
  "passed": false,
  "score": 78,
  "failed_items": [
    "Runtime context is hardcoded into the role card."
  ],
  "fix_advice": [
    "Move runtime context into a separate Context section."
  ],
  "summary": "The prompt is close, but it mixes stable role identity with runtime context."
}
```

Keep `failed_items` concrete. Each item should point to a fixable problem.
